## 2. Cybersecurity คืออะไร?

**Cybersecurity** คือกระบวนการและเทคโนโลยีที่ใช้ในการ

> ปกป้อง **ข้อมูล (Data)** และ **ระบบ (Systems)** จากการโจมตี การเข้าถึงโดยไม่ได้รับอนุญาต การแก้ไข หรือการทำลาย

เชื่อมโยงกับ 3 แกนหลัก: **CIA Triad** (จะลงลึกในหัวข้อถัดไป)

### เป้าหมายของ Cybersecurity

* ป้องกันไม่ให้คนที่ไม่เกี่ยวข้อง **เห็น** / **แก้ไข** / **ทำให้ระบบล่ม**
* ทำให้ระบบมันยัง **ทำงานต่อไปได้** แม้จะมีปัญหาหรือถูกโจมตีบางส่วน
* บริหาร **ความเสี่ยง (Risk)** ให้ยอมรับได้ (ไม่มีระบบที่ “ปลอดภัย 100%”)

### Cybersecurity ไม่ใช่แค่…

* ไม่ใช่แค่ลง **แอนตี้ไวรัส** แล้วจบ
* ไม่ใช่แค่เรื่องของ “แฮกเกอร์” แต่เกี่ยวกับ:

  * กระบวนการ (Process)
  * คน (People)
  * เทคโนโลยี (Technology)

## 3. ขอบเขต: Personal / Organization / Critical Infrastructure

### 3.1 ระดับ “เราเอง” (Personal Security)

* โทรศัพท์ / Notebook
* Social Media (Facebook, IG, TikTok, X)
* E-Wallet / Mobile Banking
* รูป / วิดีโอ / เอกสารส่วนตัวใน Cloud

**ถ้าโดนโจมตี** → บัญชีถูกยึด, เงินหาย, รูปส่วนตัวรั่วไหล, ชื่อเสียงเสียหาย

---

### 3.2 ระดับ “องค์กร / มหาวิทยาลัย”

ตัวอย่างในมหาวิทยาลัย:

* ระบบลงทะเบียนเรียน → เกรด, ตารางเรียน
* ฐานข้อมูลนักศึกษา → เลขบัตร, เบอร์ติดต่อ, ที่อยู่
* ระบบ HR / เงินเดือนของบุคลากร
* ระบบอีเมลภายใน

**ถ้าโดนโจมตี** → ข้อมูลส่วนบุคคลรั่วไหล, ระบบใช้ไม่ได้, ความเชื่อมั่นลดลง

---

### 3.3 ระดับ “โครงสร้างพื้นฐานสำคัญ”

* โรงพยาบาล → ข้อมูลคนไข้, ระบบห้องฉุกเฉิน
* ระบบไฟฟ้า / น้ำประปา
* ระบบขนส่ง: รถไฟ, รถไฟฟ้า, ตั๋วออนไลน์
* ธนาคาร, ระบบชำระเงิน

**ถ้าโดนโจมตี** → กระทบ “ชีวิตจริง” ของคนจำนวนมาก ไม่ใช่แค่ข้อมูลในคอม

## 4. คำศัพท์พื้นฐาน: Asset / Threat / Vulnerability / Risk

### 4.1 นิยามสำคัญ

* **Asset (ทรัพย์สิน)**
  สิ่งที่มีคุณค่า ต้องการปกป้อง
  → ข้อมูล, ระบบ, อุปกรณ์, ชื่อเสียงองค์กร

* **Threat (ภัยคุกคาม)**
  สิ่งที่อาจทำให้ Asset เสียหาย
  → แฮกเกอร์, Malware, พนักงานเผลอคลิกลิงก์, ภัยธรรมชาติ

* **Vulnerability (ช่องโหว่)**
  จุดอ่อนที่ Threat ใช้โจมตีได้
  → Password ง่าย, ไม่อัปเดต patch, config ผิด, ใช้ HTTP ไม่ใช่ HTTPS

* **Risk (ความเสี่ยง)**
  ความน่าจะเป็น + ความรุนแรงของผลกระทบ
  → “มีโอกาสแค่ไหน” + “เสียหายแค่ไหน”

---

### 4.2 ตัวอย่าง: ระบบ Mobile Banking

```text
ระบบ: Mobile Banking แอปธนาคารบนมือถือ

Asset:
  - เงินของลูกค้า
  - ข้อมูลบัญชี / ประวัติธุรกรรม
  - ชื่อเสียงธนาคาร

Threat:
  - แฮกเกอร์เขียน Malware ขโมยรหัส
  - Phishing ล่อให้เหยื่อกรอก OTP
  - คนใกล้ตัวแอบหยิบมือถือไปใช้

Vulnerability:
  - ผู้ใช้ตั้ง PIN เป็น 1234 / วันเกิด
  - มือถือไม่ล็อกจอ / ไม่มี fingerprint
  - ติดตั้งแอปจากแหล่งไม่ปลอดภัย

Risk:
  - เงินถูกโอนออกไปยังบัญชีม้า
  - ข้อมูลการเงินถูกนำไปขายต่อในตลาดมืด
  - ลูกค้าเสียความเชื่อมั่นในธนาคาร
```

> 🔎 **คิดตาม**:
> ลองมองมือถือของตัวเองตอนนี้ → มี Asset อะไร? Vulnerability อยู่ตรงไหน?

## 5. CIA Triad – แกนกลางของ Information Security

```text
           +----------------------+
           |   C  – Confidentiality   |
           +----------------------+
            \                    /
             \                  /
              \                /
               \              /
                \            /
           +----------------------+
           |   I – Integrity          |
           +----------------------+
                /            \
               /              \
              /                \
             /                  \
            /                    \
           +----------------------+
           |   A – Availability       |
           +----------------------+
```

CIA Triad คือมุมมอง 3 ด้านที่ใช้คิดเรื่อง Security:

---

### 5.1 C – Confidentiality (การรักษาความลับ)

**คำถามหลัก:**

> “ข้อมูลนี้ ใคร ‘ควร’ เห็นได้บ้าง?”

ตัวอย่าง:

* นักศึกษา → เห็นได้เฉพาะเกรดของตัวเอง
* อาจารย์ → เห็นเกรดของรายวิชาที่ตนสอน
* เจ้าหน้าที่ทะเบียน → เห็นข้อมูลนักศึกษาทั้งระบบ
* คนภายนอก → ไม่ควรเห็นอะไรเลย

**เครื่องมือที่ใช้ช่วย C:**

* Authentication (การพิสูจน์ตัวตน) → Username/Password, OTP, Biometrics
* Authorization (กำหนดสิทธิ์) → Role-based access control
* Encryption (การเข้ารหัส) → HTTPS, Disk Encryption, End-to-End Encryption

---

### 5.2 I – Integrity (ความถูกต้องและครบถ้วนของข้อมูล)

**คำถามหลัก:**

> “ข้อมูลนี้ถูกแก้ไขโดยใคร เมื่อไร และถูกต้องไหม?”

ตัวอย่าง:

* ยอดเงินในบัญชี → ห้ามเปลี่ยนโดยไม่มีการทำธุรกรรม
* เกรดนักศึกษา → ห้ามแก้ลับหลัง / ต้องมีประวัติว่าใครแก้
* รายการสั่งซื้อใน E-Commerce → ห้ามเปลี่ยนจำนวนเงิน/สินค้าแบบเนียน ๆ

**เครื่องมือที่ใช้ช่วย I:**

* Hash / Checksum (เช่น SHA-256)
* Digital Signature / Certificate
* Audit Log / Versioning / History

---

### 5.3 A – Availability (ความพร้อมใช้งาน)

**คำถามหลัก:**

> “ระบบ/ข้อมูลนี้ ต้องพร้อมใช้แค่ไหน? Down ได้นานแค่ไหน?”

ตัวอย่าง:

* ระบบลงทะเบียนเรียน → ถ้าล่มช่วง Add/Drop = โกลาหล
* ระบบโรงพยาบาล → ถ้าล่มตอนห้องฉุกเฉินทำงาน = อันตรายต่อชีวิต
* ระบบโอนเงิน PromptPay → ถ้าล่มช่วงเทศกาล = ลูกค้าบ่นทั้งประเทศ

**เครื่องมือที่ใช้ช่วย A:**

* Load Balancer, Auto-scaling
* Backup & Restore
* Redundancy (หลาย Data Center)
* DDoS Protection

## 6. วิวัฒนาการของภัยคุกคาม (History Brief)

### Timeline แบบย่อ

```text
1980s: Virus ยุคแรกบน PC
  - แพร่ผ่านแผ่นดิสก์, ทำเครื่องรวน, ลบไฟล์

1990s: Internet Worms
  - Morris Worm → ทำให้เห็นว่า Internet ทั้งเครือข่าย “ล่มพร้อมกัน” ได้

2000s: Mass-mailing Worms & Botnets
  - สร้าง Botnet หลายล้านเครื่อง ยิงสแปมและ DDoS เว็บไซต์

2010s: APT & Ransomware
  - การโจมตีระยะยาวแบบมีเป้าหมาย (รัฐบาล, โรงงาน, โรงพยาบาล)
  - Ransomware เริ่มเรียกค่าไถ่เป็นล้าน ๆ

2020s: Ransomware-as-a-Service + AI Attacks
  - ใคร ๆ ก็ “เช่า” เครื่องมือโจมตีได้
  - ใช้ AI ช่วยเขียนโค้ด / สร้าง Phishing / Deepfake
```

Key Message:

> จากไวรัสเล่น ๆ → กลายเป็น “อุตสาหกรรมอาชญากรรมไซเบอร์” ที่มี **ทีม Dev / QA / Support** ของตัวเอง

## 7. Modern Threat Landscape 2025

มองภัยคุกคามยุคใหม่ได้เป็น 3 กลุ่มใหญ่ ๆ

### 7.1 กลุ่ม Data Threats

* **Ransomware**
  เข้ารหัสข้อมูลทั้งองค์กร → เรียกค่าไถ่
  ปัจจุบันนิยมทำ **Double Extortion**:

  * เข้ารหัสข้อมูล
  * ขโมยข้อมูลไปด้วย → ขู่ปล่อยข้อมูลถ้าไม่จ่าย

* **Data Breach / Data Leak**
  ข้อมูลส่วนตัว / บัตรเครดิต / Log-in หลุดจากระบบ
  → ถูกนำไปขายใน Dark Web

---

### 7.2 กลุ่ม People Target (โจมตี “คน”)

* **Phishing**
  ส่ง Email/SMS/LINE ปลอม → หลอกให้กรอก username/password หรือ OTP

* **BEC (Business Email Compromise)**
  ปลอมอีเมลผู้บริหาร → ขอให้โอนเงิน / เปลี่ยนเลขบัญชีบริษัทคู่ค้า

* **Deepfake & AI Phishing**
  ใช้ AI สร้างเสียง / หน้า “เหมือนจริงมาก” โทรหาบัญชีฝ่ายการเงินให้โอนเงิน
  หรือใช้ AI เขียน email ภาษาเนียนเหมือนคนเขียน

---

### 7.3 กลุ่ม Availability Threats

* **DDoS (Distributed Denial of Service)**
  ยิงทราฟฟิกจำนวนมหาศาลใส่เว็บ/ระบบ → ทำให้คนใช้งานจริงเข้าไม่ได้

* **Sabotage / Outage**
  พยายามทำให้ระบบล่ม เช่น ลบ config, ปิดเครื่อง, ทำลาย hardware

---

## 8. Mini Case Study (ตัวอย่างกรณีศึกษา)

### เคสสมมติ: “โรงพยาบาลเมือง A โดน Ransomware”

**สถานการณ์ย่อ:**

* โรงพยาบาลเมือง A ใช้ระบบเวชระเบียนอิเล็กทรอนิกส์ (EHR)
* พนักงานคนหนึ่งเผลอเปิดไฟล์แนบในอีเมลที่ดูเหมือนมาจากบริษัทอุปกรณ์การแพทย์
* Malware รันในเครื่อง และเจาะเข้าเครือข่ายภายใน
* ข้อมูลเวชระเบียนคนไข้ถูกเข้ารหัสทั้งหมด ระบบนัดหมาย / ห้องผ่าตัดใช้ไม่ได้
* กลุ่มผู้โจมตีเรียกค่าไถ่ “เป็นเงินคริปโต” ภายใน 7 วัน
* ขู่จะ “ปล่อยข้อมูลคนไข้” หากไม่จ่าย

---

### วิเคราะห์ด้วยกรอบคิด Cybersecurity

**Asset**

* ข้อมูลเวชระเบียนคนไข้
* ระบบนัดหมาย / ห้องผ่าตัด
* ชื่อเสียงของโรงพยาบาล

**Threat**

* กลุ่ม Ransomware Gang ที่หวังผลประโยชน์ทางการเงิน

**Vulnerability**

* พนักงานขาดความรู้เรื่อง Phishing
* ไม่มีระบบ EDR / Antivirus ที่ตรวจจับพฤติกรรมแปลก ๆ ได้
* มีการแชร์ credential บัญชี admin บางส่วน

**Risk / Impact**

* กระทบ **Availability**: ระบบใช้ไม่ได้ คนไข้ไม่ได้รับการรักษาตามกำหนด
* กระทบ **Confidentiality**: ข้อมูลเวชระเบียนอาจถูกปล่อยหรือขาย
* กระทบ **Integrity**: ข้อมูลบางส่วนอาจถูกแก้/เสียหาย

---

### คำถามชวนคิด (ในห้องเรียน)

1. ถ้าเราเป็น **CISO** ของโรงพยาบาลนี้ จะทำอย่างไรบ้างใน 24 ชั่วโมงแรก?
2. จะป้องกันเหตุการณ์คล้าย ๆ กันในอนาคตอย่างไร (ด้าน People / Process / Technology)?
3. ถ้าข้อมูลถูกปล่อยออกไปจริง ควรแจ้งคนไข้ / หน่วยงานรัฐ / สื่ออย่างไร?

## 9. กิจกรรมในชั้น (Workshop สั้น ๆ)

> เป้าหมาย: ให้ นศ. “คิดแบบวิศวกรความมั่นคงปลอดภัย” กับเหตุการณ์จริง

**รูปแบบกิจกรรม:**

* แบ่งกลุ่ม 4–5 คน
* อาจารย์แจกข่าวเหตุการณ์โจมตีจริง (เช่น Data Breach, Ransomware, Phishing)
* ให้แต่ละกลุ่มตอบคำถามบนกระดาษ A3 หรือ Google Slide:

1. ระบบ / องค์กรที่โดนโจมตีคือใคร?
2. Asset หลัก ๆ คืออะไรบ้าง?
3. Threat Actor น่าจะเป็นใคร / กลุ่มไหน (เช่น Cybercrime, Insider, Nation-state)?
4. Vulnerability ที่น่าจะมีคืออะไร?
5. กระทบ CIA อะไรบ้าง (C / I / A)?
6. ถ้าเราเป็นทีม Security จะเสนอแนวทางป้องกันหรือบรรเทาอย่างไร 3 ข้อ

**Presentation:**

* เลือก 2–3 กลุ่มออกมาเล่าให้เพื่อนฟัง
* อาจารย์เสริม: มุมมองทางเทคนิค + มุมมองธุรกิจ

## 10. การบ้านสัปดาห์ที่ 1

> **รูปแบบ**: รายงานสั้น 1 หน้า (PDF / Google Docs)

### โจทย์

1. เลือกข่าว/บทความเกี่ยวกับเหตุการณ์โจมตีไซเบอร์จริง 1 เคส

   * ควรเป็นเหตุการณ์หลังปี 2022
   * เลือกจากข่าวไอที/ข่าวทั่วไปก็ได้ (ไทยหรือต่างประเทศ)

2. เขียนสรุป 1 หน้า ประกอบด้วย:

   * เล่าเหตุการณ์โดยย่อ (What happened?)
   * วิเคราะห์ด้วยคำศัพท์:

     * Asset
     * Threat
     * Vulnerability
     * Risk
   * วิเคราะห์ผลกระทบด้าน **C / I / A**
   * เสนอแนวทางลดความเสี่ยงหรือป้องกันล่วงหน้า อย่างน้อย 2–3 ข้อ

     * เช่น ปรับ policy, เพิ่มการฝึกอบรม, ใช้เทคโนโลยีเสริม ฯลฯ

3. ส่งงานผ่านระบบที่อาจารย์กำหนด (เช่น LMS / Google Classroom)

## 11. สรุปท้ายคาบ (Checklist)

ก่อนจบสัปดาห์ที่ 1 ลองเช็กตัวเองว่า:

* [ ] อธิบายคำว่า **Cybersecurity** ใน 2–3 ประโยคได้
* [ ] แยก **Asset / Threat / Vulnerability / Risk** จากตัวอย่างง่าย ๆ ได้
* [ ] วาดรูป / อธิบาย **CIA Triad** พร้อมตัวอย่างแต่ละด้านได้
* [ ] เล่าได้คร่าว ๆ ว่าภัยคุกคามไซเบอร์พัฒนามาอย่างไรจนถึงยุค Ransomware & AI
* [ ] มองข่าวโจมตีไซเบอร์แล้ววิเคราะห์เชิง Cybersecurity ได้เบื้องต้น
